## Термины

| Термин | Определение |
|---|---|
| Legacy QR | Существующий QR-код на корпусе камеры, содержащий строку с информацией о камере. |
| Universal QR | Новый QR-код, содержащий ссылку на страницу-роутер и информацию о камере. Используется для подключения камеры. |

## 1. Мотивация

Анализ обратной связи показал, что после покупки и распаковки камеры у пользователей возникают вопросы о дальнейших шагах, в процессе подключения много «отвалов», а общее впечатление — «вообще ничего не понятно». С этими вопросами пользователи обращаются в техподдержку, что указывает на недостаточный онбординг (он начинается с коробки и инструкции внутри неё).

## 2. Цель

Реализовать единый механизм подключения новых камер через QR-код, который:

- даёт пользователю более простой «вход» в сервис;
- сохраняет основное предназначение — добавление камеры в аккаунт пользователя;
- в будущем позволит выдавать пользователю более точные инструкции по подключению камеры.

После сканирования QR-кода пользователь должен автоматически перейти к сценарию подключения камеры независимо от:

- наличия мобильного приложения;
- состояния авторизации (можно перенести на последующие этапы);
- модели камеры.

Архитектура решения должна обеспечивать централизованное управление конфигурацией моделей камер без изменения формата QR. При этом должна сохраняться поддержка существующих камер с Legacy QR.

## 3. Пользовательские сценарии

### Сценарий 1. Сканирование кода при наличии приложения и авторизованном пользователе
**Предусловие:** Приложение установлено, пользователь авторизован

1. Пользователь сканирует QR-код камерой телефона.
2. Приложение перехватывает ссылку.
3. Приложение извлекает код модели и серийный номер камеры.
4. Приложение определяет формат QR.
5. Для нового формата QR приложение запрашивает конфигурацию модели через Backend API. Конфигурация получена?
   - **Да** → на основании конфигурации определяется сценарий и запускается флоу подключения камеры. Повторно вводить серийный номер не нужно.
   - **Нет** → сервер доступен?
     - **Да** → отобразить ошибку «Модель камеры не найдена, повторите попытку подключения» и вернуть пользователя к началу флоу подключения.
     - **Нет** → отобразить ошибку «Сервер недоступен, повторите попытку подключения» и вернуть пользователя к началу флоу подключения.

### Сценарий 2. Сканирование кода при наличии приложения и неавторизованном пользователе
**Предусловие:** Приложение установлено, пользователь не авторизован

1. Пользователь сканирует QR-код камерой телефона.
2. Приложение перехватывает ссылку и запоминает код модели и серийный номер камеры.
3. Пользователь проходит все шаги авторизации (логин и пароль, 2FA).
4. Приложение извлекает из сохранённой ссылки код модели и серийный номер камеры.
5. Приложение определяет формат QR.
6. Для нового формата QR приложение запрашивает конфигурацию модели через Backend API. Конфигурация получена?
   - **Да** → на основании конфигурации определяется сценарий и запускается флоу подключения камеры. Повторно вводить серийный номер не нужно.
   - **Нет** → сервер доступен?
     - **Да** → отобразить ошибку «Модель камеры не найдена, повторите попытку подключения» и вернуть пользователя к началу флоу подключения.
     - **Нет** → отобразить ошибку «Сервер недоступен, повторите попытку подключения» и вернуть пользователя к началу флоу подключения.

### Сценарий 3. Сканирование кода при отсутствии приложения
**Предусловие:** Приложение не установлено

1. Пользователь сканирует QR-код.
2. Открывается страница-роутер.
3. Страница-роутер определяет платформу устройства.
4. Пользователю отображается короткая инструкция из трёх шагов и кнопка «Скачать приложение».
5. После нажатия кнопки:
   - для iOS открывается страница приложения в App Store;
   - для Android открывается магазин приложений в соответствии с правилами, определёнными на этапе технического проектирования.
6. После установки и первого запуска приложение автоматически продолжает подключение камеры (см. [сценарий 1](#сценарий-1-сканирование-кода-при-наличии-приложения-и-авторизованном-пользователе)).

## 4. Требования

### 4.1. Требования к QR-коду

**Назначение.** QR-код — единая точка входа в сценарии онбординга и подключения камер.

**Требования**

- Обеспечить отсутствие ошибок распознавания:
  - **генерация** — технические требования к QR-коду:
    - QR-код читается стандартными мобильными сканерами;
    - quiet zone — не менее 4 модулей со всех сторон;
    - уровень коррекции ошибок — не ниже Medium;
    - цветовая схема — чёрно-белая;
  - **печать** — размеры QR-кода и качество печати.
- QR-код содержит:
  - URL с «коротким» доменом, который зависит от поверхности нанесения QR-кода:
    - коробка;
    - quick start guide (руководство по быстрому запуску);
    - корпус камеры;
  - код модели камеры;
  - полный серийный номер камеры.
- При формировании ссылки используются только символы верхнего регистра (upper case).

### 4.2. Требования к странице-роутеру

**Назначение.** Страница-роутер — единая точка входа после сканирования QR-кода. Она обеспечивает маршрутизацию пользователя.

**Требования.** Страница-роутер должна:

- принимать запросы по HTTPS;
- определять платформу пользователя (по user-agent);
- обеспечивать возможность перехвата ссылки мобильным приложением (если оно установлено);
- отображать короткую текстовую инструкцию:

  > Добро пожаловать в [Название сервиса]! Настройка камеры несложная — обычно это занимает пару минут.
  >
  > 1. Скачайте приложение.
  > 2. Зарегистрируйтесь.
  > 3. Добавьте камеру.

- отображать кнопку «Скачать приложение» и формировать ссылку на соответствующий магазин приложений:
  - для iOS — App Store;
  - для Android — в соответствии с правилами выбора магазина приложений. Возможный вариант:
    - Android с сервисами Google — Google Play;
    - Android без сервисов Google — Huawei AppGallery;
- обеспечивать возможность сбора метрик аналитики (реализация на последующих этапах).

Страница-роутер не содержит бизнес-логики подключения камеры и не принимает решений о способе подключения.

Страница должна быть адаптирована для мобильных экранов и десктопной веб-версии.

### 4.3. Требования к мобильным приложениям

При переходе в магазин приложений со страницы-роутера необходимо передать через магазин tracking ID, в том числе с данными из QR-кода (код модели и серийный номер камеры).

Мобильные приложения должны поддерживать:

1. **Перехват ссылки из QR-кода** при сканировании камерой смартфона или сторонним приложением-сканером.
   - В QR-коде используется ссылка, которая перенаправляет на страницу-роутер, если мобильное приложение не установлено.
   - Если приложение установлено, ссылку перехватывает приложение и запускает флоу подключения камеры.
2. **Одновременную работу с двумя форматами QR:**
   1. **Legacy QR** (текущий сценарий) — приложение использует существующий механизм подключения без изменений.
   2. **Universal QR** — новый формат QR.
3. **Обработку Universal QR.** Приложение должно:
   1. автоматически определить формат QR;
   2. извлечь код модели и серийный номер;
   3. запросить конфигурацию модели через Backend API и обработать ошибки (в каждом случае прервать процесс и вернуть пользователя к началу подключения);
   4. определить сценарий подключения на основании ответа Backend:

      | Ответ API | Поведение клиента |
      |---|---|
      | Один способ подключения | Показывать только этот способ |
      | Несколько способов, один передан как `priority` | Показывать все способы, `priority` — первым в списке |
      | Один или несколько способов, `priority` пустой | Считать приоритетным первый способ в списке |

   5. при необходимости выполнить авторизацию пользователя;
   6. после успешной авторизации автоматически продолжить подключение без повторного сканирования QR-кода.

### 4.4. Требования к Backend

**Назначение.** Backend предоставляет мобильному приложению информацию о модели камеры и способах подключения, необходимую для выбора сценария.

**Требования.** Backend должен предоставлять API получения конфигурации модели по её коду.

Минимальный состав ответа (MVP):

- полное наименование модели камеры;
- приоритетный способ подключения;
- перечень поддерживаемых способов подключения.

Архитектура API должна позволять расширять ответ дополнительной информацией без изменения формата QR.

Должны быть предусмотрены сообщения об ошибках:

- сервер недоступен;
- модель камеры по коду не найдена.

### 4.5. Требования к справочнику моделей

**Назначение.** Справочник моделей — единый источник информации о моделях камер. Backend использует его для получения конфигурации модели.

Каждая модель камеры должна иметь уникальный код модели (`modelnumber`), который используется в новом формате QR и при запросе конфигурации.

**Требования к `modelnumber`:**

- обязателен для всех моделей камер;
- уникален;
- длина — 3 символа;
- допустимые символы — A–Z (кроме I и O во избежание ошибок) и цифры 0–9;
- в QR-коде всегда записывается в верхнем регистре;
- после присвоения модели не изменяется.

**Миграция существующих моделей.** Всем моделям, уже присутствующим в справочнике, должен быть сформирован и присвоен уникальный `modelnumber`.

**Создание новых моделей.** При создании модели в справочнике система автоматически формирует и присваивает уникальный `modelnumber`, удовлетворяющий требованиям выше.

Сгенерированный код используется:

- при формировании QR-кодов;
- при запросе конфигурации модели через Backend API.

### 4.6. Требования к API конфигурации модели

**Назначение.** API предоставляет мобильным приложениям конфигурацию модели камеры.

**Пример ответа**

```json
{
  "vendor_id": "vendor",
  "model_id": "model-x",
  "aliases": [
    "Model X",
    "Model X L",
    "Model X LS",
    "Vendor Model X"
  ],
  "methods": ["qr", "sn", "mac"],
  "priority_method": "qr",
  "5ghz": false,
  "id": "vendor--model-x"
}
```


**Требования.** В MVP API должно возвращать:

- название модели в человекочитаемом формате — «как написано на коробке» (например, не `ABC-1234`, а `Vendor ABC-1234`);
- приоритетный способ подключения;
- перечень поддерживаемых способов подключения;
- для Wi-Fi-камер — поддержку 5 ГГц.

Архитектура API должна позволять расширять ответ дополнительными данными о модели без изменения контракта API. В перспективе могут быть добавлены:

- изображение камеры;
- персонализированная инструкция;
- описание поведения светодиодов;
- дополнительные параметры сценария подключения.

Приоритетный способ подключения должен быть обязательным полем при добавлении новых моделей. Для существующих моделей поле заполняется по правилу:

- если у камеры один способ подключения — он становится приоритетным;
- если способов несколько — приоритет в порядке: QR-код → серийный номер (SN) → MAC-адрес.

### 4.7. Правила работы с QR-кодами новых и существующих моделей

#### 4.7.1. Добавление новых моделей

При добавлении моделей в справочник для каждой модели формируется `modelnumber`.

Предполагаемый сценарий:

1. Продакт со стороны embedded-разработки приносит список новых моделей и загружает их в справочник моделей.
2. Для каждой модели генерируется `modelnumber`.
3. Продакт выгружает список нужных моделей со сформированными `modelnumber`.

#### 4.7.2. Передача нового шаблона QR на производство

После формирования `modelnumber` нужно выгрузить список моделей с соответствующими `modelnumber` и передать на производство вместе с требованиями к параметрам QR-кода (см. [4.1](#41-требования-к-qr-коду)).

#### Примеры QR

- **Старый (текущий):** <изображение>.
- **Новый:** <изображение>.

Мобильные приложения и страница-роутер принимают оба варианта scheme.

## 5. MVP

В MVP входят:

- новый формат QR;
- страница-роутер;
- поддержка «коротких» доменов и редиректоров;
- поддержка Universal QR в мобильных приложениях;
- API получения конфигурации модели.

В MVP не входят:

1. Глубокая аналитика поведения пользователя на странице-роутере и в мобильных приложениях.
2. Добавление и обработка приложениями новых данных о модели камеры:
   1. изображения моделей камер;
   2. персонализированные инструкции;
   3. индивидуальное описание поведения светодиодов;
   4. изменение существующих экранов подключения;
   5. дополнительные параметры сценариев подключения.
3. Хранение QR-кода в АДМИНПАНЕЛИ для отправки пользователю, если код на коробке утерян.
