## Глоссарий

| Термин | Определение |
|---|---|
| Карусель баннеров | Визуальный компонент с обложками баннеров, содержащих предложения для пользователя (маркетинг, новые услуги ЛК, биллинг и т. д.). |
| Карточка баннера | Подробная информация о предложении для пользователя с целевым действием. |
| Приоритетный баннер | Особый вид показа баннера — попап в нижней части экрана. |

| Компонент | Статус |

## 2. Мотивация

Коммуникация с пользователем важна для продвижения новых возможностей продукта и удобства использования уже имеющихся возможностей системы.

Сейчас push-уведомления выполняют только функцию оповещения о произошедшем событии (видеоаналитика, статус камеры, готовность архива и т. д.). При этом у них нет функции вовлечения и удержания: уведомления не ведут пользователя никуда, кроме ростера камер и списка экспортированных роликов, хотя это могло бы улучшить пользовательский опыт.

Эти функции частично реализованы в email-уведомлениях, но такой способ неэффективен:

- уведомлений слишком много;
- нужно переходить в отдельное приложение;
- email устаревает по сравнению с push-уведомлениями.

Также есть спрос на аддоны с мобильных устройств: их активно оплачивают с мобильных, значит, есть доля мобильных пользователей, которым нужно показывать акции. Но в мобильных клиентах нет подходящего инструмента.

Одно из решений — карусель баннеров в веб- и мобильном клиенте. Она показывает пользователю предложения, позволяет ознакомиться с ними подробнее и направляет на целевое действие (в разделе ЛК или на внешнем ресурсе).

## 3. Цель проекта

1. Создать карусель баннеров с карточками предложений.
2. Создать в АДМИНПАНЕЛИ инструмент для создания баннеров из готовых элементов.
3. Связать карусель баннеров и push-уведомления (out of scope).

## 4. Обзор решения

### 4.1. Концепция

#### Карусель баннеров

> **Job Story.** Когда я, сотрудник отдела маркетинга, запускаю новую акцию для сервисов компании, я хочу размещать баннеры в ЛК, чтобы пользователи узнавали об акциях в том же клиенте.

Карусель баннеров находится на видном месте в клиенте и автоматически прокручивает добавленные в неё карточки баннеров. Из карусели можно перейти в карточку баннера и посмотреть её содержимое полностью. В карточку баннера также можно попасть из push-уведомления об акции.

Баннеры планируется оформлять в едином графическом стиле силами контент-дизайнера или команды продуктовых дизайнеров.

### 4.2. Сценарии использования

#### Создание баннера

1. Сотрудник отдела маркетинга переходит в раздел создания баннеров.
2. Сотрудник заполняет поля баннера и выбирает оформление.
3. Сотрудник указывает свой ID пользователя АДМИНПАНЕЛИ для предварительной проверки баннера в выбранных клиентских приложениях в своём аккаунте.
4. При сохранении баннера сотрудник видит дату и время действия баннера, выбранные группы пользователей, клиенты и user options — чтобы не опубликовать черновой вариант.

#### Открыть карточку баннера из push (внутренний ресурс)

1. Пользователь получает push-уведомление.
2. Пользователь нажимает на push-уведомление.
3. Открывается карточка баннера.
4. Пользователь нажимает на ссылку в карточке.
5. Открывается раздел клиента (если он реализован в клиенте).

#### Открыть карточку баннера из push (внешний ресурс)

1. Пользователь получает push-уведомление.
2. Пользователь нажимает на push-уведомление.
3. Открывается карточка баннера.
4. Пользователь нажимает на ссылку в карточке.
5. Открывается внешний ресурс.

#### Открыть карточку баннера из push (биллинг)

1. Пользователь получает push-уведомление.
2. Пользователь нажимает на push-уведомление.
3. Открывается карточка баннера.
4. Пользователь нажимает на ссылку в баннере.
5. Открывается раздел пополнения баланса или тарифный менеджер (в мобильном клиенте открывается веб-версия).

## 5. Требования

### 5.1. Требования к созданию и управлению баннерами (АДМИНПАНЕЛЬ)

- **FR-1.1. Создание сущности.** Система должна позволять создать баннер с типом «Карусельный баннер / Рекламный баннер» на отдельной вкладке. Тип баннера изменить нельзя.
- **FR-1.2. Текстовые поля:**
  - поддержка Markdown (списки, курсив, жирный, заголовки);
  - поддержка разных языков (уже реализована в баннерах-полосках).
- **FR-1.3. Валидация медиа:**

  | Тип | Мин. размер | Соотношение сторон | Формат | Макс. вес |
  |---|---|---|---|---|
  | Иконка | 1600 × 1600 px | Строго 1:1 | PNG | 5 МБ |
  | Фон | 1600 × 600 px | Строго 16:6 | PNG | 5 МБ |

- **FR-1.4. Библиотека ассетов.** Система должна позволять выбирать изображения из заранее созданного списка иконок и фонов. Иконки должны удовлетворять требованиям раздела [5.1.2](#512-готовые-наборы-ассетов-для-создания-баннеров).
- **FR-1.5. Поля нового баннера.** Для нового типа баннера нужно выбрать необходимые поля и заполнить их:
  1. ID баннера (задаётся при создании), например `2024-01_promo_spring_sale`.
  2. Заголовок баннера — текстовое поле.
  3. Полное описание акции — текстовое поле с полными условиями акции.
  4. Короткое описание акции — текстовое поле с короткими условиями акции.
  5. Атрибут `unmarkable` — всегда `true`.
  6. Дата начала показа баннера (обязательно).
  7. Дата окончания показа баннера (обязательно).
  8. Партнёры, для которых отображается баннер.
  9. Группы, для которых отображается баннер.
  10. Пользователи, для которых отображается баннер.
  11. User options, для которых отображается баннер.
  12. Клиенты и их версии, в которых показывается баннер.
  13. Страны, для которых отображается баннер.
  14. Настройки фона для короткого и полного описания акции. Можно выбрать:
      1. изображение на фоне;
      2. градиент из готового набора — пара градиентов для тёмной и светлой темы.
  15. Иконка баннера — изображение в высоком разрешении (можно загрузить своё или выбрать из готового набора).
  16. Целевое действие — клиент и ссылка на целевое действие (внешний ресурс или раздел клиента). Ссылка может различаться в зависимости от клиента.
  17. Переключатель уведомлений — включены ли уведомления по баннеру. Если включены, отображается поле для текста уведомления.
  18. Текст уведомления (если уведомления включены).
  19. Тип показа баннера:
      1. **По умолчанию** — только в карусели.
      2. **Приоритет** — в заметном формате (попап).

     Приоритетный баннер может быть только один: тот, который отмечен как приоритетный и у которого флаг «Приоритет» установлен позже всех.

     > **Пример.** Баннер `banner_a` отмечен как приоритетный 01.01.2026, баннер `banner_b` — 05.01.2026. Если оба активны одновременно, в приоритетном виде показывается `banner_b`.

#### 5.1.1. Представления баннера

Тексты и графика, добавленные пользователем, используются в двух представлениях баннера:

1. **Короткий формат** — используется в карусели баннеров.
2. **Полный формат (карточка)** — отображает полную информацию о баннере и содержит целевое действие (ссылку).

Для обоих форматов должны быть доступны варианты:

- **Составной баннер** — поля баннера настраиваются по отдельности и размещаются по чёткой структуре.
- **Кастомный баннер** — загружается единое изображение, которое отображается вместо отдельных полей: как баннер в коротком формате и как фон карточки в полном формате. Заполнять поля не нужно.

> Пример кастомного баннера: _изображение удалено_.

**Поля кастомного и составного баннера**

| Поле | Составной баннер | Кастомный баннер |
|---|---|---|
| `title` | Обязательно | — |
| `text` | Обязательно | — |
| `long_text` | Опционально | Обязательно |
| `banner_icon` | Обязательно | — |
| `background_image_url` | Опционально (выбирается либо градиент, либо ссылка на изображение фона) | Обязательно |
| `background_gradient` | Опционально | — |

**Логика заполненных полей**

Структура баннера общая, но в режиме «Приоритет» карточка отображается по-разному в зависимости от заполненных полей:

1. Если заполнено длинное описание, в режиме «Приоритет» отображается кнопка «Подробнее», которая открывает карточку с полным описанием. Если для клиентского приложения заполнена ссылка на целевое действие, отображается кнопка целевого действия, иначе кнопка не отображается.
2. Если заполнены только обязательное короткое описание и ссылка на целевое действие для клиентского приложения, вместо кнопки «Подробнее» отображается кнопка целевого действия, иначе кнопка не отображается.

#### 5.1.2. Готовые наборы ассетов для создания баннеров

> **Job Story.** Когда я, сотрудник отдела маркетинга, запускаю новую акцию для сервисов компании, я хочу создавать баннеры в АДМИНПАНЕЛИ из готовых изображений и текста, чтобы баннеры имели общий стиль и на подготовку материалов для акции в ЛК уходило меньше времени.

Чтобы маркетинг мог оперативно запускать баннеры, нужно добавить выбор оформления из списка готовых изображений, соответствующих требованиям к формату и размеру.

Готовые изображения загружаются на CDN набором разных размеров (для оптимизации сетевой нагрузки): композиция, текст и соотношение сторон одинаковы во всех размерах, меняется только разрешение. Клиенты запрашивают вариант, соответствующий размеру контейнера и плотности экрана.

Требования к именованию:

- имя файла ассета — `{asset_name}_w{n}`, где `asset_name` — название ассета (отображается в списке ассетов АДМИНПАНЕЛИ), `w{n}` — ширина изображения в пикселях;
- в АДМИНПАНЕЛИ ассеты отображаются в выпадающем списке по `asset_name` без нижних подчёркиваний.

**Необходимый набор размеров**

| Тип ассета | Использование | Ширины |
|---|---|---|
| Icon | Крупный вид / bottom sheet | w800, w1200, w1600, w2400 |
| Icon | Карточка / карусель | w200, w300, w400, w600 |
| Кастомный баннер или фон | Все виды карточки | w800, w1200, w1600, w2400 |

`w` — ширина изображения в пикселях. Высота сохраняет исходное соотношение сторон.

> **Пример.** Для иконки `mystery_box.png` на CDN загружается набор файлов:
>
> ```text
> mystery_box_w200.png
> mystery_box_w300.png
> mystery_box_w400.png
> mystery_box_w600.png
> mystery_box_w800.png
> mystery_box_w1200.png
> mystery_box_w1600.png
> mystery_box_w2400.png
> ```

### 5.2. Требования к API

Сущность баннера необходимо дополнить новым типом — баннер для карусели.

Колонка «В ответе» — возвращается ли поле на клиент при получении перечня баннеров.

| Атрибут | Тип | Описание | В ответе |
|---|---|---|---|
| `id` | string | ID баннера, заданный сотрудником. | + |
| `unmarkable` | boolean | Баннер нельзя пометить просмотренным. | − |
| `title` | dict | Локализованные заголовки баннера. Если клиент явно не задал `language`, передаются все локализации.<br>Пример: `{'ru': 'текст', 'en': 'text'}` | + |
| `text` | dict | Локализованные короткие тексты баннера с поддержкой Markdown. Если клиент явно не задал `language`, передаются все локализации.<br>Пример: `{'ru': 'текст', 'en': 'text'}` | + |
| `long_text` | dict | Локализованные полные тексты баннера с поддержкой Markdown: ссылки, форматирование (жирный, курсив), нумерованные и маркированные списки. Если клиент явно не задал `language`, передаются все локализации.<br>Пример: `{'ru': 'текст', 'en': 'text'}` | + |
| `start_date` | timestamp | Левая граница диапазона дат в формате Unix time. | + |
| `end_date` | timestamp | Правая граница диапазона дат в формате Unix time. | + |
| `partners` | list | Список идентификаторов партнёров, для которых отображается баннер. Если пусто — показывать всем. | − |
| `groups` | list | Список идентификаторов групп, для которых отображается баннер. Если пусто — показывать всем. | − |
| `countries` | list | Список кодов стран, для которых отображается баннер. Если пусто — показывать всем. | − |
| `users` | list | Список идентификаторов пользователей, которым показывается баннер. Если пусто — показывать всем. | − |
| `user_options` | dict | Показ баннера пользователям с конкретными user options (ключ + значение). | − |
| `client_versions` | dict | Клиентские приложения и селекторы версий, для которых отображается баннер.<br>Формат: `{client_type: versions}`<br>• `client_type` — одно из `web`, `android`, `ios`, `windows`, `linux`, `macos`;<br>• `versions` — селектор версий в формате pip. | − |
| `button_text` | dict | Локализованные тексты кнопки баннера. Если не задан — кнопки нет.<br>Пример: `{'ru': 'текст', 'en': 'text'}` | + |
| `button_url` | dict | Ссылки для кнопки с учётом языка. Если не задана — кнопка просто закрывает баннер (например, как подтверждение).<br>Пример: `{'ru': 'https://example.com?lang=ru', 'en': 'https://example.com?lang=en'}` | + |
| `background_image_url` | string | Ссылка на фоновое изображение (локальное или из галереи). | + |
| `background_gradient` | string | Градиент фона из готового набора. | + |
| `banner_icon` | string | Ссылка на иконку. | + |
| `notification_flg` | boolean | Настройка на уровне баннера: отправляются ли вместе с ним push-уведомления в момент `start_date`. | − |
| `notification_text` | dict | Локализованные тексты уведомления об акции или баннере. Не заполняется, если `notification_flg: false`.<br>Пример: `{'ru': 'текст', 'en': 'text'}` | − |
| `priority_flg` | boolean | Флаг приоритетности. Если `true`, баннер дополнительно отображается как попап. | + |

Дополнительные требования:

- Уведомления по баннерам должны отключаться в ЛК пользователя отдельной настройкой, независимо от общих уведомлений аккаунта. По умолчанию они включены и приходят в момент начала действия баннера.
- При создании баннера сотрудник должен видеть выбранные группы пользователей — чтобы проверить баннер перед публикацией и не запустить его с ошибками.

### 5.3. Требования к интерфейсу

Необходимо создать следующие элементы интерфейса:

1. **Карусель баннеров.** Карусель автоматически прокручивает карточки баннеров и размещается в верхней части экрана клиента над списком камер. Если баннеров для показа нет, пустая карусель не отображается.
2. **Карточка баннера.** У карточки есть короткое представление (для карусели) и длинное (карточка). В АДМИНПАНЕЛИ баннер можно наполнить по-разному — клиент должен корректно отображать каждый вариант во всех клиентах, указанных при создании баннера.
3. **Приоритетный баннер.** Показывается поверх основной рабочей области при входе в клиент. Приоритетным считается баннер с флагом «Приоритет» = `true` и самой поздней датой обновления этого флага.

Подробные требования к интерфейсу и инструкции по созданию баннеров описаны в отдельных документах.

### 5.4. Требования к аналитике

В клиентских приложениях необходимо собирать следующие события:

| # | Событие | Статус |
|---|---|---|
| 1 | Показ баннера в карусели, empty state или приоритетном формате | Новое событие |
